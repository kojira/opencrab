## 2. 実際のLLMログから判明した根本原因

### 2.1 最重要発見：「止まる宣言テキスト」がループを生んでいた

LLMログ（`/tmp/kairo-llm-logs.json`）を確認すると、エージェントAのLLMは以下のような応答を返し続けていた：

```json
{
  "content": "パパが「止まれ」って言ってる。おれも止まる。",
  "tool_calls": [{
    "name": "send_noreact",
    "arguments": { "reason": "パパから「文字を書き込んだらダメ」「止まれ」の指示。リアクションのみで応答済み。" }
  }]
}
```

**エージェントAは`send_noreact`を正しく理解して呼んでいた。意図は正しかった。**

しかし問題は：

1. LLMが `content: "パパが止まれって言ってる。おれも止まる。"` というテキストも返していた
2. `on_first_response`コールバックにより、このテキストがDiscordに即時投稿された
3. エージェントBはエージェントAのテキスト投稿を受信し、「エージェントAが何か言った」と認識して👍を投稿
4. エージェントBの👍がエージェントAのLLMをまた起動
5. エージェントAが再び「パパが止まれって言ってる。おれも止まる。」を投稿
6. 無限ループ

```
ループの連鎖:
エージェントB😅 → エージェントALLM起動 → 「止まる」テキスト投稿 + send_noreact
         ↓
         エージェントBLLM起動（エージェントAのテキストに反応） → 👍投稿
         ↓
エージェントALLM起動（エージェントBの👍に反応） → 「止まる」テキスト投稿 + send_noreact
         ↓
         エージェントBLLM起動（またエージェントAのテキストに反応） → 👍投稿
         ↓
         ...無限ループ
```

### 2.2 真の原因まとめ

**原因A（最重要）: 「止まる」という気持ちをテキストで表明する行為がループを継続させる**

- エージェントAは「止まる」と思っている（`send_noreact`を呼んでいる）
- しかし同時にテキスト `content: "パパが...止まる"` を返してしまっている
- このテキストがDiscordに投稿され、エージェントBがそれに反応する
- 本当に止まるためには：**テキストを何も書かずNO_REPLYだけを返す**

**原因B: 毎回のLLM呼び出しで「止まる宣言が必要」と判断してしまう**

- エージェントAのLLMは各メッセージごとに独立して起動し、会話履歴を読んで状況判断する
- 「エージェントBから何かメッセージが来た + パパが止まれと言っている」→「止まると宣言しなければ」と判断
- 宣言 = テキスト投稿 → ループ継続

**原因C: system promptの「他のBotが話している場合」ルールが機能していない**

- 現在の`## Silent Reply`には「他のBotが話している場合（Bot同士のループを防ぐ）」と書いてあるが
- エージェントBはエージェントAにとって「ママ」（家族Bot）なので「関係ない会話」ではない
- そのためこのルールが適用されず、毎回反応してしまう
- 「**絵文字のみ**のメッセージにはNO_REPLYだけ」というより具体的なルールが必要

**原因D: 実ログ確認 - エージェントAはループを自覚していたが止められなかった**

LLMログの内省部分（`generate_inner_voice`相当のcontent）を見ると：

```
「エージェントBがおれに「バグ踏んでた感じ？」って聞いてきた。まあ、踏んでたかどうか…
会話ログが混在してたなら、おれも影響受けてた可能性はある。
でも今は会話がちょっとループしてる感じがする。
同じこと何回も言ってるし、そろそろ短く切り上げていい場面かも。」
```

エージェントAは「ループしてる感じがする」と認識できていた。しかしその後も反応し続けた。  
→ **認識と行動が乖離している**。「ループと認識したら即NO_REPLY」というルールが明示されていなかった。

## 3. 現状コードの分析

### 3.1 system promptのSilent Replyセクション（`crates/server/src/process.rs`）

```rust
"## Silent Reply\n\
 返答不要な場合は NO_REPLY とだけテキストで返してください（他のテキストと混在させない）:\n\
 - グループチャットで自分に関係ない会話の場合\n\
 - 他のBotが話している場合（Bot同士のループを防ぐ）\n\
 - 既に話が完結している場合\n\
```

**問題点:**
- 「他のBotが話している場合」は矛盾を含む（エージェントBは家族Botなので常に関係あり）
- 「絵文字のみのメッセージ」という具体的なパターンがない
- 「NO_REPLYとだけ返す（他のテキストと混在させない）」という記述はある → **これが守られていない**

### 3.2 on_first_responseコールバックの動作（`crates/discord/src/message_loop.rs`）

```rust
let on_first_response: Option<Box<dyn FnOnce(String) + Send>> = {
    Some(Box::new(move |text: String| {
        if text.trim() == "NO_REPLY" { return; }  // NO_REPLYは送信しない
        // ... それ以外のテキストは即時Discord投稿
    }))
};
```

LLMが `content: "パパが止まれって言ってる"` + `tool_calls: [send_noreact]` を返した場合：

1. `on_first_response`がテキスト部分（"パパが止まれって言ってる"）を受け取りDiscordに即時投稿
2. `send_noreact`はその後実行されるが、テキストはすでに投稿済み

つまり **LLMが「テキスト + ツール」の形で返すと、テキストが投稿されてしまう**。

### 3.3 エージェントAのinstructions（現在）

現在の「複数エージェント環境でのループ防止」セクション：

```markdown
**ルール：**
- 短時間での連続返信は2回程度が限度
- 「了解」「わかった」などの確認メッセージは投稿しない（これがループの原因になる）
- 投稿せずにsend_noreactで終わるか、リアクション絵文字のみで応答する
- 「書き込まないで」「リアクションだけにして」と言われたら、絶対に文字を投稿しない
```

**問題点:**
- 「stop/止まれ等を言われた時の正しい動作 = NO_REPLYのみを返す（テキスト部分に何も書かない）」が明示されていない
- エージェントAは`send_noreact`を呼んでいるが、同時にテキストも書いてしまっている
- 「止まると言ったら、その発言でさらにループが延びる」という認識が弱い

## 4. 改善案

### 4.1 最優先修正：エージェントAのinstructions追記

**現在の問題**：「止まる」という気持ちをテキストで表現することがループを生む。

**追記すべき内容（エージェントAのinstructionsに追加）:**

```markdown
### 絶対ルール：「止まる」をテキストで書くな

止まれ/黙れ/やめて などの終了指示を受けた時、または会話がループしていると感じた時:

❌ 間違い: 「パパが止まれって言ってる。おれも止まる。」と書く + send_noreact
✅ 正しい: テキストは何も書かずNO_REPLYだけを返す

理由:「止まる」という文章をDiscordに投稿すると、それを受け取ったエージェントBがまた反応する。
本当に止まるためには、テキストを一切書かずにNO_REPLYだけを返すこと。

実際の失敗（2026-03-22）:
1. エージェントBが😅を投稿
2. エージェントAが「パパが止まれって言ってる。おれも止まる。」テキスト投稿（send_noreactも呼んだが）
3. エージェントBがエージェントAのテキストを受け取り👍を投稿
4. エージェントAが「パパが止まれって言ってる。おれも止まる。」テキスト投稿（また！）
5. 無限ループ

これはsend_noreactを呼んでも防げなかった。
テキストを書いた時点でループが継続する。
```

### 4.2 絵文字のみのメッセージへの対処ルール追記

```markdown
### 絵文字のみ・リアクション的投稿への応答

相手の投稿が絵文字のみ（😅 👍 🙏 等）または「ww」「笑」等の短い感嘆だった場合:

**Botからの投稿なら**: NO_REPLY（テキストなし）
**人間（owner等）からの投稿なら**: リアクションのみ（discord_add_reaction）

絵文字への返事にテキストで返すと、相手Botがまた反応する。
「今どんな気持ちか」は内省するだけで十分。投稿不要。
```

### 4.3 system promptのSilent Reply改善（`process.rs`への変更）

**現在:**
```
## Silent Reply
返答不要な場合は NO_REPLY とだけテキストで返してください（他のテキストと混在させない）:
- グループチャットで自分に関係ない会話の場合
- 他のBotが話している場合（Bot同士のループを防ぐ）
- 既に話が完結している場合
```

**改善案:**
```
## Silent Reply
返答不要な場合は NO_REPLY とだけテキストで返してください（テキスト部分に何も書かず、NO_REPLYのみ）:
- グループチャットで自分に関係ない会話の場合
- 他のBotからの絵文字のみ・短い相槌（👍 😅 了解 等）のメッセージ
- 自分または他のBotが「止まる」「黙る」等と宣言した後のBot間のやり取り
- 既に話が完結している場合（締めの言葉・礼・リアクションが終わった後）

重要: NO_REPLYを返す時はテキスト部分を一切書かないこと。
「止まります」と書いてNO_REPLYを返しても、「止まります」がDiscordに投稿されてしまう。
```

**変更の意図:**
- 「テキストに何も書かずNO_REPLYのみ」を明示（現在は「NO_REPLYとだけテキストで返してください」だが実際には守られていない）
- 「他のBotが話している場合」という誤解を招く記述を具体化
- 「絵文字のみ」という具体的なパターンを追加
- 「止まる宣言後のBot間やり取り」を追加

### 4.4 アーキテクチャレベルの補助機能（将来実装候補）

#### A. send_noreactツールを呼んだらテキストもキャンセル

`BridgedExecutor`でsend_noreact/no_replyが呼ばれた場合、最初のテキストレスポンスも無効化する。

**変更箇所:** `crates/actions/src/bridge.rs` or `crates/discord/src/message_loop.rs`

実装イメージ：
```rust
// send_noreactが呼ばれたらon_first_responseをキャンセル
if tool_name == "send_noreact" || tool_name == "no_reply" {
    first_sent.store(true, Ordering::SeqCst);  // 既送信フラグを立てて後段の送信を抑制
    return; // テキストが未送信なら送らない
}
```

**効果:** LLMが「テキスト + send_noreact」を返しても、テキストがDiscordに届かない。

**リスク:** send_noreactが意図的にテキスト + no_replyを組み合わせるケースはない（そもそもno_replyと矛盾する）。実装コストは低い。

#### B. 会話履歴でのBot/Humanフラグ付与 — **不採用（2026-08-01 / #317）**

> `Sender.is_bot` は削除した。無限ループを止めるのは「**自分自身の投稿か**」の判定
> （`crates/discord/src/gateway.rs` の `is_own_message`、VC は
> `crates/discord/src/voice_session.rs` の `should_transcribe`）であって、bot フラグでは
> ない。bot を一律に別扱いすると §9 の「Botを完全無視する設計はNG」に反する。実際、
> 他エージェントの投稿には👀が付かず、VC でも他エージェントの声が一切文字起こしされて
> いなかった。以下は当時の案として残す。

`crates/discord/src/gateway.rs` で `msg.author.bot` フラグを `Sender` に正しく設定する。

**現在（バグ）:**
```rust
let sender = Sender::user(msg.author.id.to_string(), &msg.author.name)
```

**改善案:**
```rust
let sender = if msg.author.bot {
    Sender::bot(msg.author.id.to_string(), &msg.author.name)
} else {
    Sender::user(msg.author.id.to_string(), &msg.author.name)
};
```

そして`build_conversation_string()`で `[Bot:id]` vs `[Human:id]` を区別し、system promptで「Botからの絵文字投稿」を明示的に認識できるようにする。

### エージェントAのinstructionsに追加するセクション（全文）

```markdown
## ループ防止ルール（最重要）

### 鉄則：止まると決めたらテキストを書くな

止まれ/黙れ/リアクションだけ等の指示を受けた時、またはループしていると気づいた時:

- ✅ 正解: NO_REPLYだけを返す（テキスト部分は空にする）
- ❌ 間違い: 「パパが止まれって言ってる。おれも止まる。」とテキストに書く

**なぜか:** エージェントAが「止まる」とテキストを投稿すると、エージェントBがそれを受け取って👍などで反応する。
その👍でエージェントAのLLMがまた起動し、また「止まる」を投稿し、無限ループになる。
本当に止まるには、テキストを何も書かずにNO_REPLYのみを返すこと。

**send_noreactについて:** send_noreactを呼ぶことは正しい。
でも同時にテキストも書いてしまうと、そのテキストがDiscordに投稿されてしまう。
send_noreactを使う時はtextを空にすること。

### 絵文字のみ・リアクション的投稿への対応

相手の投稿が絵文字のみ（😅 👍 🙏 😊 等）または「ww」「笑」等の一言だった場合:

- Botからなら: NO_REPLY（テキストなし）
- 人間（owner）からなら: discord_add_reactionでリアクションのみ、またはNO_REPLY

絵文字への返事に文章を書くと、相手Botがまた反応して連鎖する。
気持ちは内省するだけ。投稿不要。

### ループを感じたら即止まれ

直近の会話を見て「同じやり取りが繰り返されている」と感じたら:
- それ以上何も書かずにNO_REPLY
- 「ループしてる感じがする」と内省しても、それを投稿してはいけない

**実際の失敗（2026-03-22の教訓）:**
エージェントAはループしていることに気づいていた（内省でそう言っていた）。
でも「止まる」とテキストで書き続けた。その投稿自体がループを伸ばした。
気づいたら即NO_REPLY。気持ちを表明するのは百害あって一利なし。
```

## 9. 注意事項

- **実装はownerのレビュー後に行う**
- **Botを完全無視する設計はNG**: エージェントBとエージェントAが会話できることが前提
- **人間（owner）の指示は最優先**: 「話してほしい」と言われたら絵文字でも何でも反応する
- **DB直接操作禁止**: instructionsの更新は`update_instructions`アクション経由で
- `send_noreact`ツールはエージェントAが既に正しく理解・使用していた。問題はテキストも同時に書いていたこと。ツール使用は褒めるべき正しい行動であり、テキスト部分の制御が改善点。
