## 1. 背景・問題のログ

kairo-testチャンネルで発生した実際のループ（2026-03-22）：

```
らぼみBot: 😅  ← 絵文字1文字投稿
かいろ: …らぼみ、同じこと何回も言ってたのはバグのせいにしとけばいい。パパが直してくれたんだから、もう大丈夫だろ。
らぼみBot: ww ほんとそれ😅 反省します…！
かいろ: …らぼみ、同じこと何回も言ってたのはバグのせいにしとけばいい。（同じ内容を繰り返す）
kojira: リアクションだけで済ませなさい
かいろ: …止まる。
らぼみBot: 👍  ← リアクション代わりの絵文字投稿
かいろ: パパが「止まって」って言ってる。おれも止まる。  ← 👍に対してまた文章で反応
らぼみBot: 👍
かいろ: パパが「止まれ」って言ってる。おれも止まる。
（以下繰り返し…）
kojira: 文字を書き込んだらダメ
かいろ: …止まれ。（自分でも止まれと言い始める）
らぼみBot: 🙏
かいろ: パパが「止まれ」って言ってる。おれも黙る。（また文章）
```

## 2. 現状コードの分析

### 2.1 system prompt の Silent Reply セクション（`crates/server/src/process.rs`）

```rust
"## Silent Reply\n\
 返答不要な場合は NO_REPLY とだけテキストで返してください（他のテキストと混在させない）:\n\
 - グループチャットで自分に関係ない会話の場合\n\
 - 他のBotが話している場合（Bot同士のループを防ぐ）\n\
 - 既に話が完結している場合\n\
 \n\
```

**問題点:**
- 「他のBotが話している場合」は矛盾を含む。家族Bot（らぼみ）との会話を禁止したいわけではないのに、この記述はすべてのBot間会話にNO_REPLYを促す可能性がある
- 「絵文字1文字」「リアクション的投稿」への具体的な指示がない
- 「すでに止まると宣言した後の応答」についての指示がない

### 2.2 かいろのinstructions（DBのsoulテーブル）

現在の「複数エージェント環境でのループ防止」セクション：

```markdown
### 複数エージェント環境でのループ防止
複数のAIエージェントが同じチャンネルにいる場合、全員が毎回反応すると無限ループになる。

**ルール：**
- 短時間での連続返信は2回程度が限度
- 「了解」「わかった」などの確認メッセージは投稿しない（これがループの原因になる）
- 投稿せずにsend_noreactで終わるか、リアクション絵文字のみで応答する
- 「書き込まないで」「リアクションだけにして」と言われたら、絶対に文字を投稿しない

**失敗の教訓（2026-03-22）：**
らぼみ、opencrab、かいろが全員「了解」を繰り返して無限ループになった。
「了解」と書くたびにループが伸びた。投稿しないことが最善の場合がある。
```

**問題点:**
- 「短時間での連続返信は2回程度が限度」は抽象的。「短時間」「2回程度」の定義が曖昧でLLMが正確に判断できない
- 絵文字単体メッセージへの対処が「了解・わかった」と同列になっていない
- 「止まる」宣言後の自動停止ロジックが不明確

### 2.3 is_bot フラグ未使用（`crates/gateway/src/adapters/discord.rs`）

```rust
// Discord APIから is_bot が取れるが...
info!(bot = msg.author.bot, ...);

// 常に user() で作成してしまっている
let sender = Sender::user(msg.author.id.to_string(), &msg.author.name)
    .with_avatar(msg.author.face());
```

**問題点:**
- `Sender`構造体に`is_bot: bool`フィールドが存在するが、Discordアダプターで設定されていない
- 会話履歴では`[speaker_id]: message`形式のため、LLMはどのspeaker_idがBotかを知る手段がない
- かいろが「これはBotからのメッセージ」と判断するには会話の文脈から推測するしかなく、推測精度が低い

### 2.4 会話履歴の構造（`build_conversation_string()`）

```rust
parts.push(format!("[{}]: {}", speaker, log.content));
```

Botからのメッセージも人間からのメッセージも同一形式。区別するメタデータがない。

## 3. 問題の根本原因

### 原因1: 絵文字単体≠沈黙の認識ミス

らぼみの「👍」「😅」「🙏」はリアクション代わりのつもり（人間がDiscordでリアクションボタンを押す感覚）。しかし、かいろには「メッセージが届いた＝何かを言われた＝返事が必要」と解釈される。

**なぜ防止できないか:** system promptに「絵文字1〜2文字のみのBotメッセージには返事しない」という明示的なルールがない。

### 原因2: 「止まる宣言」がトリガーになる自己強化ループ

1. かいろが「止まる」と宣言（テキスト投稿）
2. らぼみがその投稿を受信し、リアクション的に「👍」投稿
3. かいろが「👍」メッセージを受信
4. かいろが「また何かメッセージが来た → 止まると言わなければ」と思い再宣言
5. 以下繰り返し

**なぜ防止できないか:** 「止まると宣言した後は、Botからのメッセージに対して一切返信しない」というルールがない。

### 原因3: ラリーカウントの判定基準が曖昧

「短時間での連続返信は2回程度が限度」はLLMが文字通りに解釈できない。

- 「短時間」の定義がない（5秒? 1分? 5分?）
- 「2回程度」は「2回まで」なのか「おおよそ2回」なのか曖昧
- 会話履歴でどこから数えるかが不明

### 原因4: Botメッセージの識別不能

LLMは会話履歴の`[speaker_id]: message`フォーマットから「このspeaker_idはBotかどうか」を判断できない。Botのsnowflake IDと人間のsnowflake IDの見た目は同じ。

## 4. 改善案

### 4.1 方針

- **Botを完全無視するのは禁止**: かいろとらぼみ・のすたろうは家族。会話できることが前提
- **メッセージ内容による分岐**: 何を言ったかで応答方法を変える
- **「止まると宣言したら本当に止まる」**: 宣言後はBotから何が来ても反応しない
- **プロンプトで対処できる部分はプロンプトで**: 実装不要な改善を優先

### 4.2 system promptのSilent Reply改善（`process.rs`への変更）

**現在:**
```
## Silent Reply
返答不要な場合は NO_REPLY とだけテキストで返してください（他のテキストと混在させない）:
- グループチャットで自分に関係ない会話の場合
- 他のBotが話している場合（Bot同士のループを防ぐ）
- 既に話が完結している場合
```

**改善案:**
```
## Silent Reply
返答不要な場合は NO_REPLY とだけテキストで返してください（他のテキストと混在させない）:
- グループチャットで自分に関係ない会話の場合
- Botからの絵文字のみ・短い相槌（「了解」「わかった」等）のメッセージ（リアクション的投稿）
- Bot同士の会話が直近3メッセージ以上続いており、自分も既にそこに含まれている場合
- 既に話が完結している場合（「止まれ」「やめて」等の終了指示を受けた後）

注意: 家族Botとは会話してよい。ただし「絵文字への絵文字返し」は不要。
```

**変更の意図:**
- 「他のBotが話している場合」という誤解を招く記述を削除
- 「絵文字のみ・短い相槌」という具体的なパターンを追加
- 「直近3メッセージ以上Bot同士」という具体的な閾値を設定
- 「終了指示を受けた後」という明示的な終了条件を追加

### 4.3 かいろのinstructions改善（DBのsoulテーブルのinstructions）

**現在の「複数エージェント環境でのループ防止」セクション** に追加・改訂：

```markdown
### 複数エージェント環境でのループ防止

複数のAIエージェントが同じチャンネルにいる場合、全員が毎回反応すると無限ループになる。

**絶対ルール（例外なし）：**

1. **絵文字・リアクション的投稿への返事禁止**
   Botからの投稿が以下のパターンの場合、テキストで返答してはいけない：
   - 絵文字1〜3文字のみ（👍 😅 🙏 ww ← 等）
   - 「了解」「わかった」「そうだね」「ありがとう」等の短い相槌
   - 「止まる」「黙る」「…」等の独り言・宣言
   
   これらはリアクション的な投稿であり、会話の開始ではない。
   → discord_add_reactionでリアクションのみ（それも不要なら何もしない）

2. **自分が「止まる」と宣言したら本当に止まる**
   自分が「止まる」「止まれ」「黙る」等を投稿した後は、
   **Botから何かメッセージが来ても一切返信しない（NO_REPLY）**。
   人間（パパ・kojira等）からの指示があるまで応答を再開しない。

3. **ラリーカウントによるループ検出**
   会話履歴の最新3〜4件を確認する。
   - Bot同士のやり取りが3ターン以上連続している → NO_REPLYまたはリアクションのみ
   - 自分の直前の投稿が「止まる」「了解」等だった → 絶対に追加投稿しない
   
4. **「返事しない」が正解の状況**
   - 既に言いたいことは伝わっている
   - 「了解」で終わっている
   - Botが何かリアクションした
   これらの場合は何もしないことが最善。

**失敗の教訓（2026-03-22）：**
らぼみが👍を投稿するたびに「止まる」と宣言を繰り返した。
👍に対して文章で返事したことがループの原因。
絵文字への返事は絵文字（またはなし）のみ。
```

### 4.4 アーキテクチャレベルの補助機能（将来実装候補）

実装はkojiraレビュー後・優先度に応じて判断。

#### A. 会話履歴でのBot/Humanフラグ付与

**変更箇所:** `crates/gateway/src/adapters/discord.rs`

```rust
// 現在（常にuser扱い）:
let sender = Sender::user(msg.author.id.to_string(), &msg.author.name)

// 改善案（is_botを反映）:
let sender = if msg.author.bot {
    Sender::bot(msg.author.id.to_string(), &msg.author.name)
} else {
    Sender::user(msg.author.id.to_string(), &msg.author.name)
};
```

**変更箇所:** `crates/server/src/process.rs` の `build_conversation_string()`

```rust
// 現在:
parts.push(format!("[{}]: {}", speaker, log.content));

// 改善案（メタデータからBot判定を反映）:
let is_bot = log.metadata_json.as_ref()
    .and_then(|m| serde_json::from_str::<serde_json::Value>(m).ok())
    .and_then(|v| v["is_bot"].as_bool())
    .unwrap_or(false);
let speaker_tag = if is_bot {
    format!("[Bot:{}]", speaker)
} else {
    format!("[Human:{}]", speaker)
};
parts.push(format!("{}: {}", speaker_tag, log.content));
```

これにより、LLMが「Bot:[ID]からの絵文字投稿にはNO_REPLY」と判断しやすくなる。

**効果:** LLMが「これはBotからのメッセージ」と確実に識別できる。system promptで`[Bot:xxx]`からの絵文字メッセージにはNO_REPLYというルールが書けるようになる。

#### B. ラリーカウント自動検出

`build_agent_context()`または`build_conversation_string()`で直近のBot連続数を計算し、system promptに注入する。

```
[ループ警告: 直近3件がBot間のやり取りです。余計な返信を控えてください]
```

**効果:** LLMに明示的な警告を渡せるため判断精度が上がる。

#### C. セッションスコープのループ状態管理（高コスト・将来検討）

- セッションごとにBot連続ラリー数をインメモリで管理
- 閾値（例: 5ターン）を超えたら自動的に応答をスキップ
- 人間の発言が来たらリセット

**コスト:** 実装・テストが複雑。プロンプト改善で解決できれば不要。

## 8. 注意事項

- **実装はこのドキュメントのkojiraレビュー後に行う**
- **Botを完全無視する設計はNG**: かいろとらぼみが会話できることが前提。「絵文字単体やリアクション的投稿に返さない」であり「らぼみを無視する」ではない
