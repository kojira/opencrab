# D-1006-PR-01 — peer-review identity ownership (proposal)

**Status: superseded.** The owner explicitly authorized removing the effectively unused peer-review feature rather than implementing this gateway-owned roster/eligibility proposal. The historical analysis below is retained for audit; the removal RED is `docs/evidence/issue-1006-peer-review-removal-red.md`. This proposal must not be implemented. It recorded that #1006 had not specified an active `platform='external'` peer-review roster, its administration after core `trusted_users` deletion, or an authenticated peer-review eligibility attribute. `docs/design-gateway-process-ownership.md` §7 currently says inbound carries only a generic caller role and no other external identity/policy reaches core. This proposal adds an admission decision crossing that boundary and cannot be treated as an approved implementation detail. S10 must not delete the legacy table while these reachable lookups remain.

## Historical behavior examined before the removal decision

At pre-#1006 `1e8fc85`, `server/src/peer_review.rs::resolve_reviewer` selects exactly `trusted_users(platform='external', agent_id, permission='co-agent')`: case-insensitive nonempty `display_name` match first, then only a registered numeric `user_id`. Its unavailable-list and query-failure wording and transport `mention` rendering are observable. `record_peer_review_reply` independently requires that exact platform/agent/sender membership with permission CoAgent, a leading `[Peer Review]` marker, an active session task, and an outstanding request before appending one progress record. Other messages continue as normal speech. The generic caller role is **not** part of this predicate: historical Web admits as `SaidCaller::Owner`, yet its configured author can record a verdict if separately registered as an external CoAgent. A config-only CoAgent without that row cannot. Changing this to a `CallerIdentity::CoAgent` check either denies valid Web replies or admits previously ineligible replies.

`TextDelivery` has no production provider in the inspected source; `request_peer_review` currently returns its explicit unavailable-transport error. Adding a provider or making outgoing requests work is **not** part of this proposal. `server/src/process/mod.rs::peer_reviewers_section` also queries the old roster, but is explicitly `#[allow(dead_code)]` after #920; remove that unreachable production lookup and its obsolete tests during S10 rather than introducing a new prompt section. S8's `legacy_identity_sources` preserves all eight original fields and IDs as an **inert** source record; it is not mutable admission policy.

**Superseded decision (not an implementation gate):** the proposed gateway-owned *active* peer-review roster/update authority and authenticated admission attribute were not approved; the owner chose removal instead. Existing #1006 direction alone does not settle those interfaces or the change to the documented inbound contract. The removal does not authorize real cleanup, QC/production mutation, a third writer, or deletion of historical identity records without the separate S10 guard.
