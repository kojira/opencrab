# D-1006-ID-01 — retain exact legacy gateway identity rows before S10

Status: design and RED only. Issue #1006 separates ownership without losing existing identity IDs or metadata. S8 currently writes an admission `identity_projections` row containing only normalized role and external ID. It leaves the original `trusted_users` row in core, so S8 itself does not lose it, but S10 cannot delete that row without a durable owner-side copy. REST already preserves its seven original non-platform values in core `api_principals` and is unchanged.

## D-ID1 — inert owner-side source record

Each participating Discord, Nostr, and Web store has one small `legacy_identity_sources` table, with `instance_id` and the eight verbatim schema-56 `trusted_users` columns `id,user_id,agent_id,permission,created_by,created_at,display_name,platform`. The key is `(instance_id,id)`. Values are copied as TEXT without permission normalization or rewriting; the approved instance edge identifies the destination. The record is **not** a caller policy, an authentication lookup, or a new gateway API. Existing `identity_projections` remain the sole gateway admission-policy rows, including Web's fixed historical Web-local Owner marker. Do not add concrete identity columns to core, and do not make these records cascade away on instance deletion.

**Source seam and RED:** the populated Discord fixture in `crates/gateway-migrate/tests/s8.rs` migrates `trusted_users.id='tu-discord'`. After import its destination currently has only the `(instance_id,role,external_id)` projection; assert that the destination also contains the original eight fields, including exact `id`, `permission`, `created_by`, `created_at`, `display_name` and `platform`. The missing table is the expected assertion-level RED. The same table shape applies to Web/Nostr; no redundant fixtures are required for this design checkpoint.

**Minimal GREEN:** extend the three existing S5 store schemas with this table, but do not invoke write-capable store-open initialization during S8 prevalidation. Every participating destination database file must already exist. S8 opens existing stores read-only before the matched backup: an otherwise valid S5 store may lack only this new inert table; when it already exists, validate the required columns used for the source records. Do not create a missing file, table, or any other schema before backing up the complete core-plus-destinations set.

After the matched backup, within each approved destination import transaction, `CREATE TABLE IF NOT EXISTS legacy_identity_sources` using the fixed S5 table definition, validate its required columns, and insert a source record only for each explicit approved gateway edge. Accept a byte-for-byte equal existing record on a successful rerun, and refuse a conflicting `(instance_id,id)` or incomplete/missing edge without committing destination changes. For explicit fan-out, store a separate complete record under each approved instance key. Current role projection remains unchanged. Include record keys/counts and **digests only**, never raw identities, in migration verification. An absent source row has no invented record. The table is retained independently of runtime admission; no S5 daemon reads it for authorization. This initialization is part of the existing S8 destination writer, not a third writer or a generic migration framework.

## D-ID2 — cleanup precondition and rollback

S8 retains the original core rows as today. Before S10 deletes **any** `trusted_users` source row, `verify-freeze` and the guarded second writer must prove its approved destination edge set is complete and each target record's eight columns equal the corresponding original source row, including exact permission and ID. A missing, modified, or extra conflicting target refuses cleanup without deletion. S10 never deletes a source row on the strength of normalized `identity_projections` or its fingerprint alone. An ordinary S8 rerun compares the same records without rewriting them. The pre-S8 and post-QC matched core-plus-all-participating-store backup sets remain the rollback authority; no automatic restore, runtime legacy fallback, third writer, or changed history/binding/delivery behavior is introduced.

This is a one-table preservation record for already-approved source rows, not an archive framework, new platform admission mode, permission change, schema change to core, or authority to run S10 against real data. Existing Web no-bearer Owner behavior and Discord/Nostr source-role classification remain untouched. Later S10 must independently prove the other legacy source classes before dropping their tables; this design closes only the `trusted_users` ID/metadata loss.
