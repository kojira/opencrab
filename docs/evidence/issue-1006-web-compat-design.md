# D-1006-WEB-01 — restore the pre-separation Web boundary

Status: **design proposal only; no production-source edit authorized by this document**. Scope is Issue #1006's existing Web gateway and stopped S8 migration. This corrects S5/S8 without adding an authentication mode or changing unrelated gateways. The owner must review this design before implementation.

## Baseline and correction

The pre-#1006 baseline is `1e8fc85`, immediately before the #1006 design commits. Its `crates/web-gateway/src/v3/http.rs:1,28-43,277-315` explicitly has **no Bearer**: the existing create/read/message/events routes are not bearer-gated, and an accepted loopback Web message sends `SaidContext { caller: SaidCaller::Owner, start_turn: true, ... }` unconditionally. Its `crates/web-gateway/src/v3/config.rs:1,11-20,27-42` carries `http_bind`, `core_socket`, `instance_id`, `revision`, `agent_id`, and `author_id`, requires a loopback bind, and carries no Web credential. The configured `author_id` identifies the Web sender on the generic frame; it does **not** determine the admitted caller role. The earlier inference that Web Owner was derived from a legacy Discord owner or `trusted_users` lookup is incorrect and superseded by the explicit Web `SaidContext` at this baseline.

Current S5 `crates/web-gateway/src/v3/http.rs` instead requires a Bearer header, selects a token-bound instance and Owner/TrustedUser role, and sends 401/403 without that credential. `owner.rs` requires a Web master key, decrypts a credential, and reads an `identity_projections.external_id='bearer'` role at startup. S8 requires a Web credential and restricts unrelated source identities to one bearer-compatible non-co-agent row. None of these changes is required to move Web state out of core. The intended correction is **the old loopback HTTP behavior, with durable placement and identity data owned only by Web**, not a new bearerless/bearer dual mode.

The reserved admission marker is exactly `external_id='web-local'` with `role='owner'`. It is disjoint from every approved source external ID on that instance; reject a source `user_id='web-local'` even if its source role is also Owner. Existing S5 bearer rows, if encountered, remain inert and do not authorize HTTP. If preserving a legacy source row conflicts with any reserved/existing projection key, fail for operator resolution rather than guessing an auth mapping or silently dropping the row.

**S10 blocker, not a new Web feature:** Current `identity_projections` stores role and external ID, not legacy `trusted_users.id`, `created_by`, `created_at`, `display_name`, and `platform`. S8 retains original core rows, but role/external ID plus fingerprint is **not** proof that those IDs and metadata survive S10 deletion. Do not delete **any** source identity row at S10 until a separately reviewed/tested lossless disposition for those fields across every participating gateway exists. Do not add a Web-only archival schema in this Web authentication correction.

## Adjacent audit findings excluded from D-1006-WEB-01

- The old `update_heartbeat_instructions`/`read_heartbeat_instructions` `scope="channel"` surface versus current generic session scope is a separate compatibility question; test actual old-to-new behavior at that seam before changing it. No heartbeat code is changed in this design.
- S8 approval JSON currently rejects formatting/key order/unknown fields more strictly than the typed-field-and-normalized-array contract; test an ordinary semantically equivalent approval input before changing the parser. No generalized manifest framework is included here.
- Web conversation creation/read routes, Discord `/model`, and `NO_REPLY` predate #1006 (`1e8fc85`) and are not removed. Discord/Nostr identity, delivery, REST policy, IDs, history, and valid live writes are outside this Web correction.

No #1013 delivery guarantees, #1015 relationship revalidation, #1016 migration hardening, README change, production startup, real-database migration, deployment, or cleanup is authorized here.
